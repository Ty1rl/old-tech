ROUND O WAVE A — JAM-7 / base a551fbb

Start UI (balance belongs to JAM-4 Wave B)
  Main menu New Game and the winning result's Play again open NewGame. Its authored
  scene has native mutually exclusive Easy/Hard buttons, explanations, Start/Back.
  Easy is the default for a fresh dialog. Selection exists only in that dialog;
  there is no midrun difficulty setting or second difficulty store.
  SceneManager.start_play(sandbox=false, difficulty=&"easy") passes new_run=true
  and difficulty=&"easy" / &"hard" in params through the real scene transition.
  Existing zero/one-argument calls remain valid. Unknown IDs return false without
  changing params. A room retry keeps current params. JAM-4 reads params.difficulty
  and supplies actual encounter Resources/scaling later; this UI adds no balance.

Public popup API (JAM-8 migrates arena callers; JAM-3 repair remains separate)
  SceneManager.get_popup(key:StringName)->Node returns CONTENT, never holder/dim.
  The topmost matching live content is returned, or null. Queued/deleted content
  is excluded immediately. get_popup(&"") queries the current top content for focus.
  Owned menu focus now uses this API instead of reading _popups. A caller needing
  a WeaponRepair may cast its result; don't walk wrapper child indices externally.

Shared repair display (mount belongs to JAM-3)
  Instantiate scenes/ui/repair_condition.tscn beside the model/header. Its root is
  RepairConditionView. After creation/setup and on every switch_tool, call:
      condition_view.bind_equipment(equipment, tool)
  equipment is WeaponEquipment; tool is ring / beam / cone. Bind before or after
  ready. Existing repair scene node names need no changes. Minimum size 200x155;
  parent container controls placement. The view ignores input.
  The actual equipment condition and repair_steps determine every segment. The
  repaired signal produces a brief highlight only for this tool. It never completes
  repair, spends time or alters condition. Restoring equipment from history updates
  the view too: completed repairs DO rewind. Rebinding releases the prior signal;
  bind_equipment(null, &"") clears it. Freeing a view releases engine connections.
  condition_segments.gd shares the same procedural arc math with TimeStatusHUD.

Time HUD / recovery (JAM-8 capabilities must be integrated)
  Direct reads: bound TimeController.slow_unlocked and rewind_unlocked. These are
  the shared Round O contract, absent on the A base. No fallback flags or duplicate
  capability/meter/charge store were added to production UI. Slow hints and rewind
  pips/count hide independently until unlocked; the survival meter always remains.
  Flags refresh hints without needing a new bind. Main menu no longer spoils Space.
  Emergency view is a compact authored bottom readout: actual chosen moment,
  timeline, charge count and one "Scroll to choose · Enter / click to recover" line.
  Removed repeated full-screen title/safety lesson. View is hidden outside an active
  EmergencyRewind session. Arena retains all wheel/click/Enter input and restore
  ownership; UI ignores input and does not freeze/tick gameplay or change recovery.
